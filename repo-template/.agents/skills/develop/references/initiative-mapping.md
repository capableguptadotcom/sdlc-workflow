# Initiative mapping

Use this procedure only when unresolved discovery contains multiple coordinated
outcomes or decision branches that cannot remain one coherent specification or
one discovery session. Large implementation alone is not enough.

1. Explain why one feature specification would mix unresolved outcomes.
2. Propose initiative mapping and wait for confirmation.
3. Create `initiatives/<slug>/map.md` from
   `.ai/templates/initiative-map.md`.
4. Record intended outcomes and dependency-order the decision tracks.
5. Select the constraining current track and name the next track so another
   session can resume.
6. Link only relevant research, prototypes, and settled/open decisions.
7. Return each coherent outcome to `shape-change` for its own accepted spec.
8. Create implementation tickets only after a spec has accepted, independently
   verifiable slices and the developer authorizes the configured tracker.
9. Mark the map `completed`, `paused`, or `superseded` when coordination ends.

Do not create a single enormous spec, create layer-only task lists, or treat the
initiative map as an implementation plan.
